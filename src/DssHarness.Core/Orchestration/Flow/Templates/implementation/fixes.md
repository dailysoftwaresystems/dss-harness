An issue the list says is being fixed is the recovery's: no work item fixes it or rewrites its lines. An item that
needs its fix names the issue under needs, by its id as the list gives it, and the run holds the item until that fix
has ended, so it builds on the tree the fix leaves; an item that owns a file the fix holds waits for it alike. An item
names under needs only an issue the list says is being fixed or fixed, or joined to one still being triaged: the run
holds an item that needs that one until that triage has ended, and then until the fix it goes with has.
