Each statement of a definition of done - a work item's, and the plan's own - is one a check or a person can answer
alone: a behaviour and the test that pins it, or what is true of the lines the work itself writes. It says what the
work makes true in a way that holds whatever the run's other work does to the same files - the items built beside it,
the fixes the run's recovery makes, a later round: never a count of lines, a line number, a whole output, a count over
a whole file or the tree, or a comparison of a whole file or the whole tree with the base, for that other work changes
each of them. A check that reads more than the work's own lines - a lint, a limit - is held to the lines the work
changes. A statement that compares the work's own lines with the tree before the work names the run's base commit,
never a branch: a builder works in a repository of its own that holds no branch, so `main` names nothing there.
